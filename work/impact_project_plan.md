## 1. How to Add the Next Case Study (3-Beat Framework Protocol)

To maintain a dynamic portfolio, every upcoming case study follows the Week 2 3-beat structure:

1. **Problem (The Challenge):** Detail the specific bottleneck, data constraint, or engineering friction (e.g., *Manual content auditing across millions of impression logs caused delayed site refresh cycles*).
2. **Action (What I Built):** Outline the technical solution, ML stack, and leakage-prevention choices (e.g., *Engineered a Python/Random Forest pipeline with GroupKFold cross-validation grouped by domain hash*).
3. **Outcome (What Came of It):** Share measurable results, metric improvements, and action tools (e.g., *Reduced prediction error by 36.5% over baseline heuristics and exported a prioritized triage queue*).

### Deployment Checklist for New Additions:
- Add a new subfolder in `projects/<project_name>/`.
- Include a reproducible `README.md` following standard documentation guidelines.
- Append the project card HTML component into `index.html`.
- Commit changes to `main` for automated deployment via GitHub Pages.
